# Portable mobile app API

Import `@item-systems/item/mobile` for the iOS/Android ITEM app. This public
subpath has ESM, CommonJS, declaration and React Native export conditions.
It exposes `ItemSecureTunnel`, `MicrokernelClient`, plugin clients, managers,
byte utilities and status words without importing the desktop SDK barrel.

```ts
import { ItemSecureTunnel, MicrokernelClient } from '@item-systems/item/mobile'

// Supply a bounded NFC transport and a cryptographically secure random source.
const tunnel = new ItemSecureTunnel(nfcTransport, secureRandomBytes)
const kernel = new MicrokernelClient(tunnel)
const card = await tunnel.connect()
// Verify card.uid against the user's selected card before authenticating.
try {
  await tunnel.open(pairingKey)
  const diagnostics = await kernel.getDiagnostics()
} finally {
  await tunnel.close()
}
```

`CardTransport` accepts connect, transmit and disconnect callbacks; the app
owns native NFC integration and credentials. All managers share the same
`tunnel(ins, p1, p2, data)` interface. `RandomSource` must return the requested
number of securely generated bytes (for example Expo Crypto).

## Ephemeral tunnel keys and retries

Every `open()` refreshes SELECT metadata on the existing transport before
generating a fresh host key and authenticating. This supports firmware that
advertises a new, single-use card ECDH public key on each SELECT. The SDK checks
that the refreshed UID matches the previously inspected card before sending
OPEN or an identity proof. A failed SELECT discards cached card metadata.

An authentication retry does not require another physical tap if the NFC link
is still usable. No wallet key generation or pairing is repeated. Do not cache
the card's tunnel public key as a permanent identity or reuse it in a manually
constructed OPEN. After an uncertain state-changing command, inspect the
outcome rather than replaying that command merely because reconnect succeeded.

Provider-backed firmware advertises FCI tag `A8` as
`[version=1, agreementAlgorithm, cipher=5, mac=4]`. The mobile tunnel supports
agreement algorithm `1` (secp256k1) and `2` (P-256), exposes it through
`CardInfo.tunnelProfile`, and selects the matching host ECDH curve. These are
algorithm IDs, not allocated CryptoRegistry slots. Older cards without A8 keep
the legacy P-256 interpretation. Unknown/malformed explicit profiles fail
closed, and a changed or removed profile between inspection and authentication
is rejected before OPEN. There is no automatic curve fallback. Profile metadata
is unauthenticated until the pairing-key mutual authentication succeeds.

This does not enable PIN or non-root identity authentication on firmware that
does not implement it, nor does it change the separately specified identity-proof
signature curve. Registry-backed wallet derivation must still discover the
engine slot instead of assuming slot 1; in the minimal tunnel installation,
slot 0 holds the chosen EC engine, slot 1 AES, and slot 2 MAC.

The coordinated candidate now supports explicit P-256/k1 identity challenge-v1.
See [Identity/capability migration](IDENTITY_CAPABILITIES.md) for the corrected
capability masks, `UacManager.current()`, compatibility limits and deferred
bootstrap retirement. It is not yet hardware-qualified.

For the opt-in k1-bootstrap → SECURED → in-band r1 → r1-tunnel acceptance
case, see [Tunnel profile migration](TUNNEL_PROFILE_MIGRATION.md). The runner
checks real profile/handshake changes, not just master metadata. Its current
hardware preflight is blocked; the full migration is not qualified.

## Reference and scope

`UacManager.query(uid)` returns `null` for firmware `6A83` (record not found) and
legacy `6A88`. It does not treat permission errors or a disconnected card as an
absent identity, and does not retry a query automatically.

`InBandBytecodeLoader.streamCap` sends a four-byte big-endian size followed by
AID length/AID, then uses the returned slot in P1 for STREAM and COMMIT. It
requires an exact 32-byte SHA-256 receipt matching the uploaded bytes. The
storage-aligned kernel accepts flattened CAP component bytes, not a ZIP archive,
and limits a stream to 15 payload pages (30480 bytes with standard pages).
Older two-byte-BEGIN/empty-COMMIT firmware is incompatible; no automatic fallback
is attempted. A successful hash receipt does not install an executable applet.

Protocol reference: Python SDK v3.5.0 at
`cd4c319cabbd2040699bb1ebb28c68bd379f64b3`. Python is an offline implementation
reference, never an application runtime dependency. Fixtures in
`tests/mobile/fixtures/python-reference.json` cover manager commands and the
SELECT/open/mutual-authentication/diagnostics transcript. They contain synthetic
test material, not production credentials. Run `npm run tsc` then
`npm run test:mobile`. The packed-consumer smoke also checks this public subpath
in ESM, CommonJS and TypeScript consumers.

This is the app's existing mobile implementation being published as a supported
export. It does not expose the GlobalPlatform firmware-flashing adapter or
resolve the separate GP inventory/preflight findings. Advanced optional app
extension factories are not exported here. Physical-card interoperability is
not established by offline tests.

The mobile tunnel verifies response MACs and clears its session keys on close.
Response-MAC rejection is stricter than the pinned Python response path.
Identity authentication uses explicit challenge-v1, not the historical Python
identity codec; it still needs hardware validation. UAC and VFS overlap
instruction numbers in the reference, so compatibility must be established for
the target firmware before combining these operations.
